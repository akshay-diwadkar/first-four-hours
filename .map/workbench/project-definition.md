# Project definition

- [Charter](../../skills/workbench/charter/SKILL.md): start a whole project's definition conversation, its rounds and reconciliation, and the closing Ticket handoff.
- [Charter contract](../../skills/workbench/charter/references/charter-contract.md): the five sections, provenance markers, material revisions, existing-project rules, and the `ready` gate.
- [Charter publication](../../skills/workbench/charter/references/publication.md): confirmation-bound publication as one GitHub umbrella issue, revision against a verified baseline, and each stop's repair.
- [Charter workspace and shape](../../skills/workbench/charter/README.md): the `prepare` command and the exact Authority lines the publication script reads and writes.

Charter owns project intent and never splits work; Ticket persist splits a `ready` charter. Before publication the ignored local file is the authority; after a verified publication the GitHub issue is.
