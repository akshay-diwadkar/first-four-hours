All notable changes to First Four Hours are recorded in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). [Release Metadata](REPO_VERSIONING.md#release-metadata) says when to add an entry and how a release is prepared.

## [Unreleased]

### Added

- Provision 1.2.0: offers batch-ops, an optional MCP server that now ships inside Provision. Its `batch_read`, `batch_run`, and `batch_edit` tools read many files, run several commands, or apply several edits with rollback in one call. Only after you say yes, Provision installs its `mcp` and `pydantic` packages into the Python it uses and registers the server on Claude Code, Codex, or OpenCode, or on another harness whose official documentation shows how. Where a harness cannot run a local stdio MCP server, Provision says so and skips it. On Codex and OpenCode it registers batch-ops for your user account. It replaces a same-named server entry you added yourself only after you agree. No skill needs or uses batch-ops, and the skills still need no extra packages. Declining batch-ops on a rerun, or uninstalling, removes Provision's entry after you confirm. Rerun `/provision` to get the offer. Provision's context budgets rise by 90 tokens at the top level and 1046 in references, to hold the new step and its reference.
- Provision 1.3.0: adds the `ffh-planner` agent, which runs Blueprint's whole planning stage and may start only `ffh-challenger`, `ffh-evidence`, and `ffh-researcher`. It is written only where the harness lets a subagent start subagents and `ffh-challenger` is written too; on Codex and OpenCode only after you let Provision raise `agents.max_depth` or `experimental.subagent_depth` to 2, and Provision removes that setting after you confirm. On Claude Code it keeps a one-hour prompt cache. When batch-ops is connected, Provision asks which agents read, search, run commands, and edit only through batch-ops' tools (all selected by default); batch-ops is now offered before agents are mapped. OpenCode agents move to the V2 `permissions` format. Rerun `/provision` to get them.
- Blueprint 1.15.0: when `ffh-planner` launches, Blueprint settles the questions it can already see, hands it the whole planning stage, relays its questions word for word, records your answers in the request, resumes it, and relays its final report. It falls back to planning in the main session when the planner cannot launch or cannot start the subagents it needs; without the planner it plans as before. Blueprint seals plans with contract version 1.15.0.
- Provision 3.2.0: the batch-ops grep object takes `"blocks": true` to return each hit's largest enclosing block or section up to 100 lines, merged per file, with plain rows past 20 matches. `batch_edit`'s `verify` now accepts ` ||| ` slices instead of failing in the shell and rolling back. Rerun `/provision` to update batch-ops.
- Provision 3.3.0: the batch-ops survey lists GitHub Actions run steps, Makefile targets, and package.json scripts in the surveyed folder, and says when a package.json can't be parsed. Rerun `/provision` to update batch-ops.

Reports name each continuation and artifact once, and the tool schemas drop their titles and null defaults. Each report title names the server build (`build 1a2b3c4`), so a stale installed copy shows. A read whose pattern matches nothing reports `no_match` instead of `ok`, an invalid spec reports its own error, a read handle pasted as a string reads, and a `:full` handle takes a trailing `:N-M`. `path@target:N-M` shows its lines once, verbatim. A `batch_edit` edit can give `"range": "N-M"` and `"since"`, the sha a read printed, in place of `search`; it is refused when the file changed since that read. Editing a missing file says `file not found`. A grep shares the match lines it shows across files and puts each file's count in its header, listing the files separately only when some are cut. A git diff object takes `context` and `"stat": true`. `batch_run` drops terminal escape codes, keeps the last state of a line rewritten in place, folds repeated lines, shortens long runs of one punctuation character, cuts a failing output over 8KB to its failure windows and last lines, and saves the raw stream as a named artifact whenever it drops anything, slices included. Slices apply to the output before it is condensed and break lines only at line endings, so slice line numbers and `target:` text follow the command's output, without its terminal escape codes. The survey shows a folder holding only one folder together with it, churn per folder, and paste-ready zoom calls; scopes git status and changes to its folder; lists unknowns first; gives each changed file its added and deleted lines in place of a separate diff stat; and drops the candidate list. Outlines and sections also find headings underlined by a line of one repeated character, and no longer take list items for headings. A missing `bash` on Windows suggests `powershell` or `argv`. A `grep:RE in PATH..` string searches only those paths when every one exists, instead of searching the whole folder for the literal text. The 24KB outline threshold counts the file's own bytes, not its numbered lines. batch-ops now carries a version, Provision's own, in its `README.md`. When Provision's batch-ops entry already exists, a rerun shows that entry's version beside the bundled one and offers Update (only when they differ), Keep, or Remove. After an install or update, Provision offers to append one line telling the agent to prefer batch-ops' tools to the instructions file for the install scope: `CLAUDE.md` or `AGENTS.md` as each harness reads them. ## [2.4.0] - 2026-11-12

### Added

- Temper 1.0.0: a new Workbench skill that audits an existing test suite to cut what it costs to run while keeping or raising the faults it catches. Start it with `/temper` or ask for a test-suite audit; the agent may also start it for a slow or bloated suite, but not for writing or fixing individual tests. It triages with your project's own tools, then proves each finding with mutants replayed in a throwaway copy of your project, and seals numbered `redundant`, `vacuous`, `gap`, and `rework` findings in `.first-four-hours/test-audits/<slug>/test-audit.md`. It never edits your project. Its `verify` command lets a plan confirm after the change that the remaining tests still catch each planned finding's mutants and that a trimmed suite is not clearly slower (more than 10% plus one second) than the audit measured; it reports the seconds saved. Its test design reference is the one place the suite's test-design rules live.
- Blueprint 1.14.0: plans from a sealed Temper `test-audit.md`, every finding or the ones named with `handoff_item`, the same way it plans an Assess review's findings. When it plans added or changed tests, it shapes them by Temper's test design rules if Temper is installed. Its requirement trace now covers a test audit's selected findings. Its references budget grows by 28 tokens to hold that pointer and wording. It seals plans with contract version 1.14.0.
- Construct 1.15.0: ships the Blueprint 1.14.0 runtime copy, so it reports contract version 1.14.0 and accepts plans made from a Temper test audit. It still accepts every sealed 1.x plan.
- Router 1.3.0: can route a sealed Temper `test-audit.md` with findings to Blueprint, with the user choosing which findings to plan.
- Construct 1.14.0: `verify` and `reverify` now return a readable `run_summary` with one entry per Run executed, in order. Each entry gives the Run's Blueprint line, its command, its exit code (null on a timeout or launch failure), its status (`passed`, `failed`, `timed_out`, `launch_error`, or `guard_failed`), and its last non-blank stdout and stderr lines, bounded. A completed run returns it as `result.run_summary`. When verification stops, the diagnostic's `details.run_summary` holds it, including every Run before the stopping one, which the stop envelope did not show before. Before, callers had to dig each Run's exit code and output out of the full result, and one judged an `Expect:` on exit status alone. The full `results`, `full_output`, and pass/fail behavior are unchanged. Its references budget grows by 96 tokens to hold this guidance.
- Blueprint 1.13.0: a downstream ticket can now plan from an architecture whose earlier implementation is already committed. Add `"implemented_at":"<full commit SHA>"` to the request's `architecture-source` declaration, naming the commit that implemented it. Intake still checks the architecture file, its digest, and its receipt, and requires that commit to come after the architecture's snapshot and be in HEAD's history; it no longer compares the repository with the pre-implementation snapshot or its cited lines. Before, once HEAD moved, the only routes were resealing with Architect or restating the architecture by hand. `implemented_at` cannot be combined with `predecessors`, and an architecture sealed outside Git cannot use it. A stale source's refusal now names this route. Its references budget grows by 29 tokens to hold it. It seals plans with contract version 1.13.0.

## [1.0.0] - 2026-10-25

The first public release of First Four Hours: 15 skills for coding agents. Each skill helps an agent do one job properly before it moves on: find the real cause, settle the plan, carry the plan out faithfully, or check the result that matters. The skills need Python 3.11 or later and a coding agent that loads skills; Scribe and Ticket also need extra Python packages, and the plugin routes need Git. The README describes each skill and the documentation covers installation and first use. Distributed under the MIT License.

### Added

- Workbench skills, for working on a project and its changes: Architect, Assess, Atlas, Blueprint, Charter, Construct, Diagnose, PR, and Ticket.
- Sensemaking skills, for getting ready to decide: Ideate, Reason, Router, and Scribe.
- Learning skills, for building your own knowledge and ability in any subject: Examiner and Tutor.
- Installation with the Skills CLI, which needs Node.js for `npx`: `npx skills add akshay-diwadkar/first-four-hours --skill '*'` installs the whole suite, and `--skill <name>` installs one skill.
- Installation as the `first-four-hours` Claude Code plugin on Claude Code 2.1.275 or later: `/plugin install first-four-hours --marketplace akshay-diwadkar/first-four-hours`. Plugin skills start as `/first-four-hours:<skill>`, for example `/first-four-hours:diagnose`.
- Installation as the `first-four-hours` Cursor plugin, by cloning the repository into `~/.cursor/plugins/local/first-four-hours`, or, on a Teams or Enterprise plan, by importing the repository as a team marketplace.
- Versioned formats. Every skill starts at 1.0.0, and a skill's version is also the version of every artifact, handoff, receipt, bundle, and state format it owns. A consumer accepts another minor or patch version of the same major and refuses any other version.
