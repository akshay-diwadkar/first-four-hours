# Changelog

All notable changes to First Four Hours are recorded in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). [Release Metadata](REPO_VERSIONING.md#release-metadata) says when to add an entry and how a release is prepared.

## [Unreleased]

### Added

- Blueprint 1.11.0: fewer plans pay for a fresh challenger. Code confined to one package or directory and exercised directly by its own tests, with any configuration or fixtures only those tests read, no longer makes a plan elevated by itself. Before, only a tiny plan touching one source file was exempt. A validator, a shared runtime, configuration or fixtures read by code outside the change's own package or directory, and code reaching beyond one package still elevate a plan, as do the other signals: changed budgets, contracts other skills consume, irreversible effects, and the seal runtime. The unused tiny-plan definition is removed. It seals plans with contract version 1.11.0.
- Construct 1.11.0: ships the Blueprint 1.11.0 runtime copy, so it reports contract version 1.11.0. It still accepts every sealed 1.x plan.
- Blueprint 1.10.0: a plan runs one fewer judgment pass.
  - An elevated draft's owner walk now rehearses Construct's Verification and re-derives the load-bearing premise, and leaves the Challenger brief to its one fresh challenger. Before, the planner ran the same brief itself first. A standard draft's walk still runs the brief.
  - Blueprint now consults Reason before sealing, not also before the challenge. That matches Reason's own checkpoints: before committing to an approach, after a failure, and before presenting a result.
  - It seals plans with contract version 1.10.0.
- Construct 1.10.0: ships the Blueprint 1.10.0 runtime copy, so it reports contract version 1.10.0. It still accepts every sealed 1.x plan.
- Construct 1.9.0: a passing run costs fewer tokens.
  - `verify` keeps full output for a failing Run. For a passing Run it no longer returns the whole output twice: JSON output comes back only parsed in `stdout_json`, trimmed to its final records when large with `stdout_json_omitted` giving the count dropped, and other stdout and stderr keep their final 4000 characters behind an omission note. When anything is trimmed, `full_output` names a temporary file outside the repository holding both streams whole, so an `Expect:` about omitted output can still be judged, and `notices` still lists every record the check marked slow. Previously a passing Run returned its complete output, plus a parsed copy for JSON.
  - The execution contract read at every intake is about 40% shorter. Failing Runs, `reverify`, the mutation-guard details, resume, and stopping move to a new Failure, resume, and stopping reference read only when a Run or green proof fails, on `status` resume, or before stopping. Two duplicate sentences are removed, and the references budget is unchanged.
  - It ships the Blueprint 1.9.0 runtime copy, so it reports contract version 1.9.0. It still accepts every sealed 1.x plan.
- Blueprint 1.9.0: the seal report now says to start Construct in a fresh session or subagent when possible. The sealed plan carries every decision, so Construct no longer has to carry the whole planning conversation on each of its turns. It seals plans with contract version 1.9.0.
- Blueprint 1.8.0: amending a plan after Construct stops, for example on a `plan-contradiction`, no longer means rewriting it from a blank template. Add `--predecessor /absolute/stopped/blueprint.md` to workspace preparation. It checks the stopped plan is unedited and bound to its request in this repository, reserves a fresh task directory even when the request is unchanged, and starts the new draft as the stopped plan without its receipts. It also returns which files the stopped plan bound are unchanged, changed, or missing, as `carryover` does. You edit only what the stop evidence and the applied work change, then seal. The stopped plan and its workspace stay unchanged. It seals plans with contract version 1.8.0.
- Construct 1.8.0: ships the Blueprint 1.8.0 runtime copy, so it reports contract version 1.8.0. It still accepts every sealed 1.x plan.
- Blueprint 1.7.0: a changed request no longer forces a fresh workspace and a full replan. Write the amended request outside the repository and rerun workspace preparation with `--amend` followed by the workspace's `blueprint.md` path, which preparation returned. It replaces that workspace's `request.md` in place, and a sealed plan loses its receipts and becomes a draft again, so you repair only what the change touches and seal again. If a file the seal bound has changed since, or a file the plan creates already exists, Construct may have started, so preparation refuses with `workspace.amend.progressed` and leaves the workspace untouched; prepare a fresh workspace instead. When a challenger finding needs your input, Blueprint now asks all such questions at once, records your answers by amending the request in place, and repairs only what they change. Answering no longer resets the one-challenge limit, so it no longer triggers a second full challenge. Elevated-risk signals that appear later are still re-checked. It seals plans with contract version 1.7.0.
- Construct 1.7.0: ships the Blueprint 1.7.0 runtime copy, so it reports contract version 1.7.0. It still accepts every sealed 1.x plan.
- Blueprint 1.6.0: amending a plan after Construct stops no longer forces you to reseal an unchanged architecture. An `architecture-source` declaration may now list the implemented plans as `"predecessors"`, the absolute paths of their sealed `blueprint.md` files, so a later amendment, after Construct implemented an earlier one, works too. Intake checks that each plan is unedited, belongs to this repository, and was planned from the same architecture. It then leaves those plans' Location paths out of the architecture's snapshot comparison. Any other change to the repository, or to the evidence the architecture cites, is still refused. This works for Git snapshots whose HEAD has not moved, when those paths were unchanged at the architecture's seal. A refused source now names the recovery steps: reseal with Architect, then write a fresh request with the new digest, or list the implemented plans as predecessors. It seals plans with contract version 1.6.0.
- Construct 1.6.0: ships the Blueprint 1.6.0 runtime copy, so it reports contract version 1.6.0 and reads requests that declare predecessors. It still accepts every sealed 1.x plan.

### Fixed

- PR 1.0.1: `check` now refuses a base that is not a branch, such as a commit SHA, a tag, or `origin/HEAD`, with `pr.base_not_branch`, before you are asked to confirm the text. Previously such a base passed `check` and `publish` failed only after your yes. Pass a local branch such as `main` or a fetched remote-tracking branch such as `origin/main`. `check` does not contact the remote, so a branch deleted there since your last fetch, or a local branch you never pushed, still passes.
- Architect 1.1.1: the shared architecture verifier can leave verified predecessor plans' Location paths out of a Git snapshot comparison, for Blueprint 1.6.0's amendment intake. Architect's own sealing and checks are unchanged. New handoffs record `scope_version` 1.1.1.

- Blueprint 1.5.6: its guidance is reworded to follow research on how agents read instructions, with no rule added or removed. The most consequential rule now leads each section, rules say what to do rather than only what to avoid, and syntax that `check` enforces is stated once and points to its diagnostics. The last workflow step is now Seal or stop: when the seal gate cannot hold, Blueprint stops unsealed and reports why rather than weakening an outcome, check, or proof to seal. The guidance stays about the same size, and the SKILL.md budget drops from 945 to 935 tokens. It seals plans with contract version 1.5.6.
- Construct 1.5.6: ships the Blueprint 1.5.6 runtime copy, so it reports contract version 1.5.6. It still accepts every sealed 1.x plan.
- Blueprint 1.5.5: its reference guidance is half the size, so every plan reads less. Rules that were stated in several places now have one home, and lists of diagnostic codes give way to the diagnostics' own fix text. The Elevated attack reference folds into the Challenger brief, and the Seal receipts reference into one README rule: never author, move, or edit a receipt line. A set of low-value rules is removed, among them the seal-gate entries that restated other sections, Ideate's per-outcome steps (Ideate's own contract covers them), the test-double and external-tool clauses, and interpreter pinning. Every pinned safety rule keeps its wording. Blueprint's references budget drops from 12900 to 6450 tokens, so the guidance cannot quietly grow back. It seals plans with contract version 1.5.5.
- Construct 1.5.5: ships the Blueprint 1.5.5 runtime copy, so it reports contract version 1.5.5. It still accepts every sealed 1.x plan.
- Blueprint 1.5.4: every plan now reads a shorter planning contract. Three rules that only some plans need move to the reference for their case: how to check that a test selector covers the change (Executable contracts), when exact text is earned (Declared text), and how to reuse or amend an earlier sealed plan (a new Earlier plans reference, linked from step 2). Each rule keeps its wording. Blueprint's context budget limits rise, because the reference files together grow slightly even though each plan reads less. It seals plans with contract version 1.5.4.
- Construct 1.5.4: ships the Blueprint 1.5.4 runtime copy, so it reports contract version 1.5.4. It still accepts every sealed 1.x plan.
- Blueprint 1.5.3: its instructions are easier to follow. The steps now come first, the read-only boundaries come after them, and every step ends on a check that tells the planner when it is done. Challenge and repair is done only when every finding is repaired, rejected on evidence, or returned to you, and every check the plan authors that a repair changed has been re-applied to every file, name, and text it scans. SKILL.md and its references are both shorter than before. An unverified claim now has one name, prediction, in place of three. It seals plans with contract version 1.5.3.
- Construct 1.5.3: ships the Blueprint 1.5.3 runtime copy, so it reports contract version 1.5.3. It still accepts every sealed 1.x plan.
- Blueprint 1.5.2: a repair that widens what a plan's own check matches no longer seals a plan that check fails. When a repair changes what a check matches or rejects, Blueprint now re-applies that check to every file, name, and text it scans, not only the repaired lines, and the fresh challenger looks for a check that would fail on text or names the plan drafts. It seals plans with contract version 1.5.2.
- Construct 1.5.2: ships the Blueprint 1.5.2 runtime copy, so it reports contract version 1.5.2. It still accepts every sealed 1.x plan.
- Blueprint 1.5.1: a plan no longer seals an unchecked guess about an external tool's output as fact.
  - A tool behavior that a check or verification result depends on, such as how a minifier or obfuscator writes text a check looks for, counts as fact only when a probe of the current project shows it or the plan quotes it from the documentation or source of the tool version in use. Anything inferred beyond that is labeled and carried as a risk with a decided branch, and such a check prefers a marker the tool leaves intact, often one without spaces or special characters.
  - Before sealing, each untested limit the challenger or Blueprint's own walk states that a verification result depends on must be verified, given a decided branch, or removed by narrowing that result. An unresolved one blocks the seal, as an open finding does.
  - Probes still install nothing.
  - It seals plans with contract version 1.5.1.
- Construct 1.5.1: ships the Blueprint 1.5.1 runtime copy, so it reports contract version 1.5.1. It still accepts every sealed 1.x plan.

## [2.2.0] - 2026-11-06

### Added

- Blueprint 1.5.0: a read-only `carryover` command tells a replan which files an earlier sealed plan relied on are unchanged, so it can reuse what it read from them instead of reading them again. Probes, measurements, and any fact a finding or stop disputed are still redone.

- Provision 1.0.0: a user-invoked Workbench skill, started with `/provision`, that sets up the suite in the harness it runs in. After you confirm, it installs the skills' Python requirements, then writes up to five `ffh-*` subagents (challenger, reviewer, conformance, evidence, researcher) on the model and effort you choose from your harness's current list, with its own recommendation and reason for each. Run it again to refresh stale model choices, or ask it to remove its subagents. It carries notes for Claude Code, Codex, and OpenCode and reads the documentation of any other harness. The Claude Code and Cursor plugins now hold 15 skills.

### Changed

- Tutor 1.4.0: keeps teaching in step with your course and with examination practice.
  - A continuing session starts with any review the study plan has due, before new material.
  - When you follow a course and share its materials, Tutor uses their notation and terms.
  - Work that looks assessed, such as homework or a take-home examination, gets teaching toward it: Tutor teaches the method on a parallel example and guides your own attempt, never writes the submission, and says why once. Work you say is not assessed gets ordinary help.
  - For an examination goal, each topic's name starts with its syllabus area. The study plan says what each section shows. Where Tutor's progress and Examiner's coverage disagree on an area, each notes it in its own section and the next step follows the coverage. A schedule change that no longer fits beside the plan's other sections is raised with you, with choices, instead of changing them.
  - Its guidance context budget rises to fit these rules.
- Examiner 1.4.0: practice results no longer overstate what a student has secured.
  - An area is secure, and a diagnosed gap resolved, only from marked answers to more than one question new to the student. Questions the student has seen before, such as in a retry, never count, and the plan's results mark each retry.
  - When topics are left open, it recommends first the areas the plan lists as needing work and those of topics Tutor's lessons list as unresolved, and it reads the examination's earlier papers so no question repeats one the student has seen.
  - Its section says what coverage shows and notes any disagreement with Tutor's progress, with the next step following its coverage. A schedule change that no longer fits is raised with the student, with choices, as Tutor does.
  - Its guidance context budget rises to fit these rules.
- Assess 1.5.0: each finding now shows how the problem happens.
  - A finding carries a `scenario`: short steps from a trigger to the wrong outcome, set against what should happen, each resting on the finding's cited evidence. Its defect is one plain sentence, and its consequence says who is affected and how badly.
  - The final report gives each finding's scenario with its severity and defect.
  - An assessment bundle must now give each finding a non-empty `scenario` array, and sealing refuses one without it. Assessments it seals record 1.5.0, and `check`, re-reviews, and Blueprint still accept every 1.x assessment, including ones without scenarios.
- Blueprint 1.5.0: costs less on small plans.
  - In a tiny fix, code that is one source file plus tests or fixtures exercising only it no longer earns a fresh challenger on its own. A tiny fix is one or two files, not counting docs, changelog, or version lines, with no integration, environment, or test-selection fan-out. A budget change, a cross-skill change, an irreversible effect, a seal-runtime change, or a validator, runtime, or configuration that other code reads still earns one. Blueprint still walks every draft itself, and every Reason checkpoint still runs.
  - A question that one file read or search answers no longer loads the delegation reference first.
  - A sealed Assess `assessment.md` with `findings` can be the request itself. Blueprint verifies its receipt, plans every finding or only the numbers you pass as `handoff_item` (such as `1,3`), and binds that choice into the seal. A repeated `handoff_item` is now refused instead of keeping only the last value.
  - Exact text that a validator, loader, or schema reads, such as a manifest, config, or fixture, must now pass that reader's rules, checked from source when planning, and match the keys of an existing entry of the same kind. When a rejection would block later steps, the plan adds a cheap check through that reader so Construct stops at that step. The challenger treats data its reader would reject as a finding.
  - It seals plans with contract version 1.5.0.
- Scribe 1.1.0: checks documents by their real structure, and fewer false alarms block correct documents.
  - A bundle `section` now covers its subsections, and a `#` line inside fenced code no longer starts a section. A `section` naming a heading that occurs twice is refused instead of silently using the last one. A warning now covers hazardous actions in its section's subsections.
  - Inline code is no longer read as prose, except to find hazardous actions. A bare "stop", as in "If the check fails, stop.", needs no warning, and words such as "between" or "red" no longer count as passive voice. Table cells now get the language checks.
  - Facts, procedure steps, warnings, recovery steps, prerequisites, and branches match across line wraps, backticks, bold, and italics; commands, paths, and values still match exactly.
  - A recovery step's `trigger` is now checked and must come before the step, and a prerequisite can name the `procedure` it must precede. If a procedure step, a warning or its dangerous action, a recovery trigger or step, or a prerequisite occurs more than once in its scope, as when an overview also mentions it, the check reports `ambiguous_marker` instead of deciding the order from the first mention.
  - Only `.md`, `.markdown`, and `.txt` documents get language checks, so error messages in source code get the fact and command checks alone.
  - Facts pasted into the chat can be bound as evidence files beside the temporary bundle, outside your repository.
  - Gaps use one marker, `[GAP: <missing fact>; owner: <next owner>]`; a marker quoted inside code is an example, not a gap. `write` reports `incomplete` with every gap and its owner, and `audit` lists each gap as a finding.
  - Its document bundle contract version is now 1.1.0, and every 1.x bundle is still accepted. A bundle whose recovery `trigger` text is missing from the document, or whose order-checked marker repeats in scope, now fails: correct the bundle or the document.
- Construct 1.5.0: ships the Blueprint 1.5.0 runtime copy, so it reports contract version 1.5.0 and accepts plans sealed from an Assess assessment. It still accepts every sealed 1.x plan.
- Router 1.2.0: routes a sealed Assess assessment whose result is `findings` to Blueprint.
- Blueprint 1.4.0: runs exploration questions that only read and search files on the `ffh-evidence` subagent Provision writes, and the fresh challenge on `ffh-challenger`, whose model is then the one you chose in Provision rather than one at least as capable as the planner. This entry and the six after it, through Ideate 2.1.0, also find the `ffh_` names Codex and OpenCode use, and treat a listed subagent that fails to launch as missing. Without these subagents, Blueprint delegates as before. It seals plans with contract version 1.4.0 and ships the Architect 1.1.0 handoff verifier.
- Construct 1.4.0: runs an earned conformance review on the `ffh-conformance` subagent, or on a generic subagent as before when it is missing. It ships the Blueprint 1.4.0 runtime copy, so it reports contract version 1.4.0, and still accepts every sealed 1.x plan.
- Assess 1.4.0: costs less per review.
  - When the session that wrote or planned the change runs Assess, Assess hands the whole review to one fresh-context subagent instead of reviewing on top of that session's context. If that subagent returns no checked assessment, Assess stops and asks you to run it in a fresh session. Where subagents cannot start their own, as in Claude Code, a `clear` it seals records that its optional second-look challenge did not run.
  - It reads diffs one path and range at a time, loads its Blueprint, re-review, and delegation rules only when they apply, and skips the final Reason checkpoint on a tiny change it finds clear.
  - Sealing now reports every bad locator at once. Assessments it seals record 1.4.0; `check` still accepts every 1.x assessment.
- Assess 1.3.0: runs a fresh self-authored review and falsification slices on the `ffh-reviewer` subagent and a clear challenge on `ffh-challenger`, or on generic subagents as before when they are missing. Assessments it seals record 1.3.0.
- Reason 1.2.0: runs a fresh challenge on the `ffh-challenger` subagent, or on a generic subagent as before when it is missing.
- Reason 1.3.0: can ask you several questions in one turn when no answer could change another. Its decide branch now says which disposition its result line reports.
- Architect 1.1.0: runs evidence workers on the `ffh-evidence` subagent, or on generic subagents as before when it is missing. Architecture handoffs it seals record 1.1.0.
- Diagnose 1.1.0: runs evidence workers on the `ffh-evidence` subagent, or on generic subagents as before when it is missing. Diagnoses it seals record 1.1.0; Blueprint and Construct still accept every 1.x diagnosis.
- Ideate 2.1.0: runs research workers on the `ffh-researcher` subagent, or on generic subagents as before when it is missing. Ideations it seals record 2.1.0.
- Router 1.0.3: its capability list includes Provision.
- Diagnose 1.2.0: can hand one finding to Architect when its fix first needs a structural decision, such as who owns a responsibility or which way a dependency points. Blueprint and Ideate remain the other next steps. Diagnoses it seals record 1.2.0; Blueprint and Construct still accept every 1.x diagnosis.
- Router 1.1.0: routes a Diagnose finding that needs a structural decision to Architect.

- Blueprint 1.3.0: costs less per plan. Blueprint now walks every draft itself. It launches a fresh challenger only for a plan that:
  - creates, changes, or deletes code that runs or the configuration it reads;
  - changes a time or size budget, or could use up the room left under one;
  - spreads to other skills or packages;
  - has irreversible or outward-facing effects; or
  - changes the seal runtime.

  A request gets at most one challenger and is never rechallenged. When repairs after that challenge would replace a plan's basis, Blueprint stops without sealing and names the failing premise. The seal now refuses a completion condition that names no proof the plan authors, and a command that names a file before the step that creates it. Plans may now let a verification command write Git-ignored output such as tool caches, build output, and lock files.
- Construct 1.3.0: a verification command that writes Git-ignored output, such as tool caches, build output, environment folders, or lock files, no longer stops the run. Construct no longer reads those folders before and after each command, so verification is faster in projects with large dependency or build folders. It still stops when a command changes tracked files, untracked files Git does not ignore, the Git index, or any file the plan names, ignored or not, and it now also stops when a command moves HEAD; a plan that relies on an ignored file must cite it. It never reads through a directory link. It ships the Blueprint 1.3.0 runtime copy, so it reports contract version 1.3.0, and still accepts every sealed 1.x plan.

### Fixed

- Ticket 1.0.1: no longer declares the unused `tree-sitter` packages, so it needs no extra Python packages and `/provision` no longer installs them. Scopes it seals record 1.0.1.
- Ideate 2.1.1: the sealer no longer refuses a subheading that starts like a required heading, such as `### What to do before choosing`, or a suggested follow-up containing a word like "reconstruct". Ideations it seals record 2.1.1.

## [2.1.0] - 2026-11-02

### Added

- Tutor 1.3.0: a whole course or examination's material now has two deliveries, paced (written as you progress) or up front (all written before you start). Tutor takes yours from the request or asks once, and records it in the study plan's goal. A lesson written up front counts as not started until you study it or demonstrate its topic.

### Changed

- Assess 1.2.0: the first review accounts for every removed clause and the whole lifecycle of any new state, so fewer flaws surface only on later rounds. A re-review now covers what changed since the earlier assessment and whether its findings are fixed, reports that scope with the earlier assessment's head, and names what it did not re-inspect; ask for a full review to cover the whole change again. A rebase or amend that rewrites the reviewed commit gets a full review. A self-authored change gets one fresh reviewer unless it is too large for one.
- Examiner 1.3.0: when the time or conditions are open, asks once whether you have an access arrangement such as extra time, and the on-screen paper's timing and instructions reflect it. It settles what your request implies or research establishes before asking you. Its audit rejects multiple-choice cueing: correct letters unevenly spread without a sourced reason, a correct option given away by length or qualification, or one question revealing another's answer. A follow-up set for diagnosed gaps uses questions new to you, on different surfaces from those that exposed the gaps.

## [2.0.0] - 2026-11-01

### Added

- Tutor 1.2.0: Tutor now ships scripts and needs Python 3.11 or later. `scaffold` writes a lesson, the study plan, or `START_HERE.html` from a skeleton, taking the next lesson number and never replacing a file. `check` takes the pages just saved and blocks on unfilled skeleton markers, broken relative links, missing anchors, and unreadable files. It warns, without blocking, about absolute links and about cited web pages that are dead, unverifiable, or unreachable.
- Examiner 1.2.0: Examiner now ships scripts and needs Python 3.11 or later. `scaffold` writes a practice set with the next set number and the paper runtime copied into `paper.html`, or the study plan or `START_HERE.html`, never replacing a file. `check` validates the pages just saved as Tutor's does.

### Changed

- Scribe 1.0.1: consults Reason after any failure or direction change, not only after a failed direction. Its document bundle contract version is now 1.0.1; every 1.x bundle is still accepted.
- Ideate 2.0.2: consults Reason after any failure or direction change, not only after a failed direction, including before repairing a failed seal. Ideations it seals record 2.0.2.
- Tutor 1.2.2: consults Reason after any failure or direction change, not only when a teaching approach fails, and before presenting an explanation as well as a diagnosis. Other tutoring turns skip it, because your next answer shows whether a choice worked. Reason's result line now goes where Reason places it, never inside a lesson, so an objection still open when Tutor presents its result reaches you, and Tutor's end-of-session report accounts for its checkpoints.
- Examiner 1.2.2: consults Reason after any failure or direction change, not only when a paper or marking approach fails. Reason's result line now goes where Reason places it, so an objection still open when Examiner presents marking, a diagnosis, or a paper reaches you; those lines and objections name questions by number and never reveal an answer or hint. Its final report accounts for its checkpoints.
- Charter 1.0.2: consults Reason before proposing the Purpose and after any failure or direction change, as well as before presenting the agreed charter and before accepting a material revision. Rounds skip it, because you settle each item asked and the check before presenting covers derived ones. Its close report now accounts for those checkpoints.

- Reason 1.1.0: a challenge of your agent's own non-trivial proposal or result now runs in a fresh-context subagent when a wrong one would be hard to reverse or cross a safety, security, permission, or authority boundary, including a readiness claim that clears such an action. A new Fresh challenge reference sets what that challenger gets (the target, its requirements and evidence, the challenge reference, and read-only scope, never the agent's reasoning) and returns, and how the agent rechecks the result before the disposition is its own. Skills that run their own fresh challenger, reviewer, or adversarial specialist, such as Blueprint, Assess, and Ideate, keep their own rule and get no second one. Where no subagent can start, or the host or you do not allow one, the challenge runs in the agent's own context and the reply says the fresh challenge did not run.

- Reason 1.0.2: a new Results reference, read at every consultation, settles where results go and how much rigor a decision gets. The visible result line goes on its own line outside reply content, or as a set-off first line where the host shows only the reply. Only an explicit invocation or a result you must act on puts a branch result in the reply. An objection, evidence gap, or open question still standing when a result is presented counts as resolved only by a fix, a defeating observation, your answer, or a change of direction that leaves the result no longer resting on it; otherwise it is told to you with what would settle it, and no readiness it undermines is claimed. A decision gets the full strongest-opposing-argument pass unless a check the work already runs, before the outcome is relied on, would catch a wrong choice that is cheap to reverse; a completion or readiness claim gets it unless a mechanical check settles it. Work no owner skill reports on traces its checkpoints through the visible lines, and its final reply names any missed or late checkpoint.
- Ideate 2.0.0: `ideation.md` now opens with **What to do**: an `Outcome` (`recommended direction`, `run an experiment first`, or `research limit reached`), a `Final choice` (`yours to make`, `made by you — …`, or `delegated — …`), and the recommendation or next step in plain language. **Goal and research** follows with the goal, criteria, scope, and `Research:` record, then Evidence, Exploration, **What would change the answer**, and an optional **Suggested follow-up**, replacing `## Handoff`, `## Conclusion`, `## Open questions / next discriminator`, and `## Optional downstream action`. The `composed` search shape is now `path with a fork`, and the `condition met` research stop is now `settled`. Ideate now searches the web by default, repository-scoped goals included, and the sealer refuses an ideation with no External evidence row naming a source unless research stopped for `user limit` (you said not to) or `unavailable sources`. Ideations sealed by 1.x are refused; run Ideate again to produce one in the new format.

## [1.0.0] - 2026-10-25

The first public release of First Four Hours: 15 skills for coding agents. Each skill helps an agent do one job properly before it moves on: find the real cause, settle the plan, carry the plan out faithfully, or check the result that matters. The skills need Python 3.11 or later and a coding agent that loads skills; Scribe and Ticket also need extra Python packages, and the plugin routes need Git. The README describes each skill and the documentation covers installation and first use. Distributed under the MIT License.

### Added

- Workbench skills, for working on a project and its changes: Architect, Assess, Atlas, Blueprint, Charter, Construct, Diagnose, PR, and Ticket.
- Sensemaking skills, for getting ready to decide: Ideate, Reason, Router, and Scribe.
- Learning skills, for building your own knowledge and ability in any subject: Examiner and Tutor.
- Installation with the Skills CLI, which needs Node.js for `npx`: `npx skills add akshay-diwadkar/first-four-hours --skill '*'` installs the whole suite, and `--skill <name>` installs one skill.
- Installation as the `first-four-hours` Claude Code plugin on Claude Code 2.1.275 or later: `/plugin install first-four-hours --marketplace akshay-diwadkar/first-four-hours`. Plugin skills start as `/first-four-hours:<skill>`, for example `/first-four-hours:diagnose`.
- Installation as the `first-four-hours` Cursor plugin, by cloning the repository into `~/.cursor/plugins/local/first-four-hours`, or, on a Teams or Enterprise plan, by importing the repository as a team marketplace.
- Versioned formats. Every skill starts at 1.0.0, and a skill's version is also the version of every artifact, handoff, receipt, bundle, and state format it owns. A consumer accepts another minor or patch version of the same major and refuses any other version.
