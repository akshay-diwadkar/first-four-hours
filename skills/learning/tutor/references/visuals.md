# Visuals

Read this before adding a diagram, interactive example, or animation.

Use one only when it explains a relationship, process, structure, or change that words carry poorly; decoration is not a reason.

- Prefer the simplest form that works: a labelled static diagram before an interactive example, and an interactive example before an animation.
- Match the surface: a plain-text reply gets a text diagram or table; rich visuals belong in a saved lesson or wherever the host renders them.
- An interactive example lets the learner change an input and see the effect, works with keyboard and pointer, and also states its result in text.
- An animation shows change over time. Give it play and pause and, for a sequence of steps, step forward and back; never autoplay a loop. Under `prefers-reduced-motion: reduce`, start paused or show the steps as static frames.
- Every essential idea an animation or interaction carries is also in the text or a labelled static figure, so the lesson still teaches with motion off or scripts disabled.
