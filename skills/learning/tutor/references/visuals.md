# Visuals

Read this before adding a diagram, interactive example, stepper, or animation.

Use one only when it explains a relationship, process, structure, or change that words carry poorly; decoration is not a reason.

- Prefer the simplest form that works, in this order: labelled static diagram, interactive example, stepper, animation.
- Match the surface: a plain-text reply gets a text diagram or table; rich visuals belong in a saved lesson or wherever the host renders them.
- An interactive example lets the learner change an input and see the effect, works with keyboard and pointer, and also states its result in text.
- A stepper walks a multi-stage process, such as backpropagation: one stage at a time with Back and Next, a stage count, what that stage changes highlighted, and why.
- An animation shows continuous change over time. Give it play and pause; never autoplay a loop. Under `prefers-reduced-motion: reduce`, start paused or show static frames.
- Every essential idea a stepper, animation, or interaction carries is also in the text or a labelled static figure, so the lesson still teaches with motion off or scripts disabled.
