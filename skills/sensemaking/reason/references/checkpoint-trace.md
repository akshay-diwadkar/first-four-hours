# Checkpoint trace

Read this when an owner skill whose work requires Reason checkpoints writes its final or stop report.

In that report, briefly account for each required checkpoint: the before-approach consultation, each failure or direction-change consultation (or no trigger), each further checkpoint the owner skill names, and the final consultation. Mark each consulted, missed, or pending when not yet due, and say whether it ran in fresh or owner context; never report its result. Mark a checkpoint consulted only when its consultation ended with the visible result line naming the risk it tested; otherwise it is missed.

After a miss, consult and reconsider before proceeding, and report that recovery as late, never as timely compliance. Claim no readiness or completion while a required consultation is missing. Keep the trace in the report only: no transcript, new artifact, schema, or persisted state.
