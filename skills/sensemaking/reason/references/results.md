# Results

Read this at each consultation.

## Non-trivial

A decision is non-trivial, and takes SKILL.md's full pass, unless a check the work itself already runs before the outcome is relied on would catch a wrong choice, and that choice is cheap to reverse; a later review, revert, or user report does not count. A before-presenting claim of completion or readiness is non-trivial unless a mechanical check settles it.

## The visible line

Emit the line when the consultation ends, on its own line as working output, never inside reply content such as an answer, lesson, document, report body, or artifact. Where the host shows the user only the reply, make it the reply's first line, set off from the content. The line asks nothing of the user.

## Into the reply

Only an explicit user invocation, or a result the user must act on, puts a branch's user-facing result in the reply. Otherwise the owner acts on it; besides the owner's own content, the reply carries only that set-off line where the host requires it, the open-disposition statements below, and any missed or late checkpoint [Checkpoint trace](checkpoint-trace.md) requires there.

## Open dispositions

Before presenting, take every disposition from this work's checkpoints other than no material concern: a challenge's `material-objection` or `insufficient-evidence` (the line's material objection or missing evidence), a decide result's unresolved blocker, or an ask question still unanswered. Each is resolved only by a fix, an observation that defeats it, the user's answer to the question, or a direction change after which the presented result no longer rests on the claim it attacked. State every other one in the reply: the objection, gap, or question, what would settle it, and, when you dismiss it on judgment alone, why. Claim no readiness or completion it undermines. With no owner skill's report, read [Checkpoint trace](checkpoint-trace.md) before the final reply.
