# Blueprint evidence

Read this when a sealed Blueprint for this change is available. It is authority evidence, never proof of correctness; its sibling `request.md` is the request.

- **Baseline proof.** From a checkout at the exact reviewed head with no tracked changes, run once, verbatim from its root, each `Run:` under `### After implementation` and each `**Proof run:**`, honoring `Timeout:`; skip `Red:`. Never trust Construct's report or PR claims that they passed. Each is authored to pass on a correct implementation, so a nonzero exit or unmet `Expect:` is a candidate finding. Ignored caches or locks they create are side effects. Run none that would change tracked content; never switch a checkout to reach the head.
- **Missing baseline.** A declared `Incomplete:` outcome, or a command you cannot run, leaves that proof missing: cover its surface with other focused proof or direct examination, or name it in `limitations`; `blocked` only when the gap prevents a trustworthy result.
- **Trace.** Judge each item against its clause in `request.md`, never the plan's restatement, and confirm its cited Run or Proof run would fail without the change by reading what it exercises against the diff, or the defect a `Red:` names; one a plausible wrong implementation passes is a candidate finding. Never clear an `Owner gate:` item: name it and its owner in `limitations`, and treat it as a candidate finding unless `request.md` records the user's acceptance.
- **Conformance.** Open each Location and compare it with the plan yourself, using no Construct tooling: every instruction is realized, each Exact, Edit, Replace, and Frozen block appears verbatim at head, no `deleted` target survives, and no material change exceeds what the plan and Construct's execution contract authorize. Construct's conformance report is a hint that clears nothing.
- **Premises.** Compare each `sources` sha256 in the plan's `blueprint-proof` receipt with that file's bytes at head; a Facts `**Source:**` changed since the seal outside the plan's Locations is a candidate finding against each decision resting on it.
- **Independent effort.** For each Decision, highest consequence first, construct a compliant-but-bad implementation (an open choice, dropped consumer, wrong premise, or unproven path) and check whether the code at head is one. Then check unnamed consumers and propagation, base behavior outside the plan's proof, code quality and maintainability, and proportionate security. `**Tier:** critical` earns the Behavior/Proof falsification slice.

Verify each candidate against `request.md` and current source. When the Blueprint specified or left out the defective behavior, cite its snapshot with a source locator and name the Decision in the finding's defect, so the fix plan revisits that Decision and the cases it covers. A green baseline is never `clear`: every material requirement and surface still needs accounting under the assess guidance's Reassessment and stop. A limitation the user accepted in `request.md` or other authority is not a finding while the change stays within it; one accepted without that record is a candidate finding.
