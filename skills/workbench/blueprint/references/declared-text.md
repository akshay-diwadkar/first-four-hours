# Declared text

Read this when declaring `**Exact:**`, `**Frozen:**`, or `**Proof run:**`, or on a `block.*`, `frozen.*`, or `declaration.malformed` diagnostic or a `proof.*` diagnostic about an instruction's Proof run or `Red:` line. The [planning contract](planning-contract.md) decides when a plan earns Exact text or new step proof; this file owns authoring that proof, including `Red:` and break-the-code checks, plus the declarations' grammar and seal checks.

Author new step proof as `**Frozen:**` text the executor writes verbatim and never edits, run by the step's `**Proof run:**`; a new regression declares `Red:` naming the defect it must show before the change: the wrong behavior the current source produces, traced from that source. Never predict how the failure surfaces, such as an exit code, diagnostic, exception, or first failing assertion; Construct judges whether the observed failure shows the defect. Shape the Proof run so its red is observable under the repository's runner traps: what its selector runs, where it stops after a first failure, and how it executes entry points. Its selection need only reach the regression; after-implementation verification covers the whole planned change set. Declare no `Red:` the host Construct will use cannot produce: record in Current State why the defect cannot occur there and where it can, keep the regression as ordinary proof that passes there, and start the condition it proves with `Owner gate:` naming who confirms it where the defect occurs.

Place frozen proof at the cheapest boundary that exposes the wrong outcome: a unit check when the unit decides it, a command or integration check when wiring does. A mock must not replace the operation whose result the proof claims.

Plan a break-the-code check only when ordinary proof could still pass a named material wrong outcome. It is retained frozen proof like any planned test: place it where the repository's test placement, ownership, and size rules accept it, keep it in the delivered diff, and run it only after its mutation target exists, never as the failure a `Red:` observation must show. On temporary or in-memory copies it requires the discriminating check to pass unmutated and to fail with the named failure after the named mutation, passing only then. Mutate only text the plan fixes as Exact or Frozen bytes, so every correct implementation contains the mutation target. It never edits the worktree, so it needs no restoration and trips no mutation guard.

`**Exact:** `path`` (implementation text) or `**Frozen:** `path`` (planner-authored tests or break-the-code checks the executor never edits) names one of that instruction's own Location paths. A `new` target takes one closed, unindented fenced block, its whole content; an `existing` target takes a fenced block, a standalone `**With:**` line, and a second fenced block, replacing the first block's whole lines with the second. To rewrite an existing file, quote its full content as the replaced text; an empty file, or the last line of a file without a trailing newline, cannot be declared this way and stays a specified step. Block text is the LF-delimited lines between the fences, each ending in one newline. CRLF is read as LF; other control and Unicode separators remain literal. A complete numbered instruction/Location/State sequence inside declared text, or a nested declaration with a same-character fence at least as long as its outer fence, is ambiguous and fails as `block.shape`. Standalone headings and shorter nested fence examples remain literal. At most one `**Proof run:** `command`` follows the Run command rules, then an optional `Timeout:`, an optional `Red:` naming the defect the regression must show before the change (declaring a new red-then-green regression), each at most once, and a required `Expect:` that exits `0`.

The seal rejects a block off its instruction's Locations, an unclosed or empty block, a replacement of a `new` target, a whole-file block on an `existing` one (`block.whole_existing`), a target that is not UTF-8 text (`block.target_unreadable`), Frozen proof without a Proof run, a duplicate or malformed Proof run, a repeated `Timeout:`/`Red:` (`proof.duplicate`), and a `Red:` line, or a stray `Expect:`/`Timeout:` in a step with a Proof run, that the Proof run chain does not bind (`proof.displaced`). In Implementation and Verification, a line beginning with `Exact`, `Frozen`, `With`, `Proof`, `Red`, or `Incomplete` followed by a colon is a reserved declaration. Each label binds as written above (bold `**Exact:**`, `**Frozen:**`, `**With:**`, `**Proof run:**`; plain `Red:` and `Incomplete:`) in any letter case, after optional leading spaces or tabs and an optional `-` or `*` list marker followed by whitespace. Any other spelling of a reserved label, such as plain `Exact:`, bold `**Red:**`, a `+` marker or a number followed by `.` and whitespace, backticks, or a space before the colon, is rejected (`declaration.malformed`). A line that starts with anything else, such as `>`, `1)`, or `-` with no following space, is not a declaration and is ignored; `*` with no following space reads as emphasis and is rejected. Put such prose inside a fence, or rewrap or rephrase it.

The seal then simulates a faithful executor instruction by instruction, Frozen blocks then Exact blocks, sharing one state for paths resolving to the same file: every block of a phase must be unapplied when the phase starts (`block.unprovable`), each replaced text must occur exactly once at a line boundary where it is applied (`block.anchor`), and every block applied so far must still be realized after each phase (`block.consumed`). These are the states Construct checks, so declared text a faithful executor writes always passes; widen blocks with unchanged neighbouring lines when the seal refuses. No specified edit may change a block's replaced text before its instruction or its declared text after it, because Construct applies each block at its anchor and reproves it after every later instruction and at final verification.
