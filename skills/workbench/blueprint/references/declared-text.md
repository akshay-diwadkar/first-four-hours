# Declared text

Read this when declaring `**Exact:**`, `**Frozen:**`, or `**Proof run:**`, or on a `block.*`, `frozen.*`, or `declaration.malformed` diagnostic or a `proof.*` diagnostic about an instruction's Proof run or `Red:` line. The [planning contract](planning-contract.md) decides when a plan earns each declaration; this file owns their grammar and the seal's checks.

`**Exact:** `path`` (implementation text) or `**Frozen:** `path`` (planner-authored tests or break-the-code checks the executor never edits) names one of that instruction's own Location paths. A `new` target takes one closed, unindented fenced block, its whole content; an `existing` target takes a fenced block, a standalone `**With:**` line, and a second fenced block, replacing the first block's whole lines with the second. To rewrite an existing file, quote its full content as the replaced text; an empty file, or the last line of a file without a trailing newline, cannot be declared this way and stays a specified step. Block text is the LF-delimited lines between the fences, each ending in one newline. CRLF is read as LF; other control and Unicode separators remain literal. A complete numbered instruction/Location/State sequence inside declared text, or a nested declaration with a same-character fence at least as long as its outer fence, is ambiguous and fails as `block.shape`. Standalone headings and shorter nested fence examples remain literal. At most one `**Proof run:** `command`` follows the Run command rules, then an optional `Timeout:`, an optional `Red:` naming the defect the regression must show before the change (declaring a new red-then-green regression), each at most once, and a required `Expect:` that exits `0`.

The seal rejects a block off its instruction's Locations, an unclosed or empty block, a replacement of a `new` target, a whole-file block on an `existing` one (`block.whole_existing`), a target that is not UTF-8 text (`block.target_unreadable`), Frozen proof without a Proof run, a duplicate or malformed Proof run, a repeated `Timeout:`/`Red:` (`proof.duplicate`), and a `Red:` line, or a stray `Expect:`/`Timeout:` in a step with a Proof run, that the Proof run chain does not bind (`proof.displaced`). In Implementation and Verification, a line beginning with `Exact`, `Frozen`, `With`, `Proof`, `Red`, or `Incomplete` followed by a colon is a reserved declaration. Each label binds as written above (bold `**Exact:**`, `**Frozen:**`, `**With:**`, `**Proof run:**`; plain `Red:` and `Incomplete:`) in any letter case, after optional leading spaces or tabs and an optional `-` or `*` list marker followed by whitespace. Any other spelling of a reserved label, such as plain `Exact:`, bold `**Red:**`, a `+` marker or a number followed by `.` and whitespace, backticks, or a space before the colon, is rejected (`declaration.malformed`). A line that starts with anything else, such as `>`, `1)`, or `-` with no following space, is not a declaration and is ignored; `*` with no following space reads as emphasis and is rejected. Put such prose inside a fence, or rewrap or rephrase it.

The seal then simulates a faithful executor instruction by instruction, Frozen blocks then Exact blocks, sharing one state for paths resolving to the same file: every block of a phase must be unapplied when the phase starts (`block.unprovable`), each replaced text must occur exactly once at a line boundary where it is applied (`block.anchor`), and every block applied so far must still be realized after each phase (`block.consumed`). These are the states Construct checks, so declared text a faithful executor writes always passes; widen blocks with unchanged neighbouring lines when the seal refuses.
