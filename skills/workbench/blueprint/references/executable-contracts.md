# Executable contracts

Read this when the dispatch, runtime mode, installed adapter, phase/state, wrapper semantics, or input spelling of a command, API, integration, or verification path can change its correctness.

For a command, API, integration, or verification path whose dispatch, runtime mode, installed adapter, phase/state, or wrapper semantics can change correctness, trace the authored invocation through its actual public entrypoint and dispatch to the operation, required inputs and phase/state, and observable result. A matching internal transition or same-purpose helper is not evidence of the public command or the inputs it reads; for a gate over uncommitted changes, trace which paths its entrypoint reads (index, worktree, diff), including planned deletions, renames, and new files. Behavior that depends on how an input is written (link, case, encoding, relative path) always brings the wrapper or runtime between the public command and the changed code into scope: probe the current public command with that kind of input; a library-level probe is only supporting evidence. Distinguish runtime modes; inspect the installed adapter and packaged resources when execution uses them. The affected path is every current consumer, contract, and verification surface touched by the planned diff under current ownership; follow only those contracts, not every internal helper. Declaring a touched surface out of scope requires a source pointer showing no consumer.
