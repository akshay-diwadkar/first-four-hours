# Ideate in planning

Exploration gathers facts; Ideate searches for solutions. Invoke `ideate` within planning only when no viable solution is apparent, or when materially different viable directions remain that the request and repository evidence cannot rank. A direction that evidence ranks is yours to decide without Ideate. Give it the goal, constraints, and every settled choice. It seals its own ignored `.first-four-hours/ideations/` handoff; that write is Ideate's, not Blueprint's.

Consume the result without replaying research. A direction Ideate returns is a solution choice the user owns, not a repository-derived engineering detail; details within the selected direction stay yours. A `user-selected` or `delegated` Selection stands in every state without asking again. Under an `open` Selection, by state:

- `decision-ready`: present the recommendation and viable choices and obtain the user's final selection before committing; a recommendation is never approval.
- `experiment-first`: run its named discriminator only when it is a safe probe, then present its outcome with the viable choices for the user's selection; otherwise ask the user for that evidence or a choice.
- `research-limited`: do not seal on that direction; report the limit to the user as a blocker.

Then resume planning in the same run; never return control merely to require a separate upstream Ideate stage. Record the selection as a resolved answer in the authoritative request before preparing the workspace (for supplied architecture, through the resolved-request route in architecture intake); a selection made after preparation is a changed request that supersedes the workspace. Carry its decisive evidence into Current State; never cite the `.first-four-hours/ideations/` workspace as Source.
