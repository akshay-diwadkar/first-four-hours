# Incomplete gates

A gate a correct implementation can leave incomplete for an environmental reason (a load-sensitive deadline, an unavailable service) may declare that outcome on one `Incomplete:` line directly after the last after-implementation Run's `Expect:`, so at most one per plan. Its signature excludes every outcome of planned code the output can distinguish, such as recorded failures or a failing worker exit. Declare deadline exhaustion only with Current State headroom (the deadline minus a passing current-tree probe's elapsed time) that the added work cannot plausibly consume, judged from source, never by timing an end state; without a passing baseline, return the conflict to the user. When the change can consume the headroom, declare nothing: key a decided [conditional branch](planning-contract.md#conditional-branches) to the measured time and treat exhaustion as failure. Narrow every other environment-sensitive gate, Proof runs included, to a scope a correct implementation completes, or return the conflict to the user. A declared gate still exits `0` on a healthy host; any `Timeout:` sits well past its own deadline and startup, since a Construct timeout is unsafe, never incomplete; and Construct reports a match as incomplete, never passed, without rerunning it.
