# Execution Contract

## Trust boundary

Construct consumes one sealed Blueprint and never edits it. Blueprint is the sole semantic authority for requested behavior, scope, seam, files and symbols, control flow, propagation, preservation, compatibility, safety, tests, verification, and completion. Discovery during execution can prove a contradiction, never create an obligation. The `verify` command is the mechanical establishment boundary: it validates the canonical `.first-four-hours/blueprints/<task>/blueprint.md` path, its canonical `request.md` sibling, the sealed receipts, repository and request binding, planned-source freshness, and the Git worktree before anything runs, then executes exactly the requested phase's authored Run entries. Repository-internal execution and a Blueprint sealed under another contract major fail closed.

Read [Failure, resume, and stopping](failure-and-resume.md) when a Run or green proof fails, on `status` resume, and before stopping.

## Execute literally

Construct follows the sealed `Implementation` section in order. It must not redesign, choose a different seam, add consumers, tests, cleanup, compatibility, abstractions, robustness, propagation, API surface, or proof breadth; trim authored work; replace authored verification; run a second YAGNI review; or absorb a newly discovered semantic obligation. Construct writes the code realizing the authored behavior, interfaces, pseudocode, and prose-specified tests; `apply` writes declared Exact and Frozen text verbatim. Pseudocode fixes decisions, not wording, and grants no license to redesign; a pseudocode decision that conflicts with repository facts is a `plan-contradiction`. Beyond those decisions Construct chooses only local details Blueprint intentionally does not care about, such as syntax glue, formatting, imports, and inconsequential local naming. If two choices can materially alter behavior, ownership, API shape, control flow, propagation, test strategy, compatibility, recovery, or acceptance, Construct must not decide between them: stop with the exact missing Blueprint obligation.

A change that is mechanically necessary to realize an authored instruction stays within non-semantic mechanical fallout: syntax/import/reference repair, or regeneration of authoritative derived output the authored instruction already implies. Changes that alter behavior, policy, ownership, validation scope, typing scope, budgets/exceptions, compatibility, capability meaning, or planned scope are never incidental: if the sealed Blueprint does not authorize one, stop with `plan-contradiction` and the exact missing obligation. An extra material change that serves no instruction is not silently kept: remove it, or stop when source reality proves it genuinely necessary.

| Situation | Required behavior |
|---|---|
| Code disagrees with a settled plan instruction | Correct the implementation and rerun invalidated authored verification. |
| Syntax, imports, references, or other mechanical fallout has a determined repair | Repair locally within the declared scope. |
| An authored Run fails because the host sandbox denied a permission the command needs, not because of a code defect | Request that permission and rerun the same authored Run unchanged; never rewrite the Run or substitute an interpreter. |
| A behavior, environment, compatibility, ownership, or verification decision is missing or contradicted | End the Construct invocation and return exact evidence to Blueprint through the caller. |
| Protected work conflicts make continuation unsafe | End this invocation as `protected-work-conflict` (see [Stopping](failure-and-resume.md#stopping)); Construct does not restore or continue. |
| Concurrent changes, verification mutation, or uncertain timeout cleanup make continuation unsafe | End this invocation as `safety-contradiction` (see [Stopping](failure-and-resume.md#stopping)); never resume from the drifted state. |

Correcting code to match an explicit ordering requirement is implementation repair. Choosing a new environment or weakening a test gate is not automatically incidental merely because it appears operational.

## Verification

`verify` runs authored Run commands verbatim from the repository root: one exact argv command per Run, the authored `Timeout:` honored (default 900 seconds), process-tree cleanup on timeout, output returned in the result (full on failure; on a pass, bounded and given once, parsed as `stdout_json` when JSON), and a per-step mutation guard over the Git index, HEAD, and [guarded content](failure-and-resume.md#mutation-guard). A failing, timed-out, or repository/index/worktree-mutating Run stops the runner with the step summary and captured output as evidence; nothing is persisted. A timed-out or repository/index/worktree-mutating Run ends this invocation as `safety-contradiction` (see [Stopping](failure-and-resume.md#stopping)). `Before implementation` entries run only through phase `before`; when none are authored, the phase returns only the independently necessary establishment checks and no invented test result. After-implementation entries run only through phase `after`, after every authored instruction has been applied.

`Expect:` is agent judgment over the returned output; scripts prove exit, timeout, mutation, and declared exact text only, and never judge whether the code satisfies an instruction. A record a check itself marks `"slow": true` appears in `notices` on verify, prove, status, and their partial results as information that never changes pass/fail. Exit 0 does not excuse an unmet Expect. Judge every authored `Expect:` against the returned output; an unsatisfied Expect with no authored branch and no Blueprint-settled correct answer is a Blueprint contradiction, not a local repair target. Do not substitute a larger suite, add neighboring tests, or broaden proof.

## Step proof

An instruction may declare `**Exact:**` text, `**Frozen:**` proof text the executor never edits, and one `**Proof run:**`. A block with one fence is a new file's whole content; a fence, `**With:**`, and a second fence replace the first text with the second in an existing file. Each block is `exact` (whole file equal, or the replacement occurs exactly once at a line boundary with the replaced text gone outside it), `unapplied` (new file absent, or the replaced text occurs once and substituting it would be `exact`), or `diverged`. Comparison is UTF-8 text with CRLF read as LF. The seal proves every check below passes on its declared text; undeclared edits to the same files can still contradict.

- **Apply.** `apply` writes one instruction's declared blocks so the executor never hand-copies them: `blocks=frozen` or `blocks=exact` selects one kind, and omitting it applies Frozen then Exact, which a `Red:` instruction with Exact text refuses because its red comes first. It replays the seal's simulation on the current files: earlier instructions' blocks and, for Exact text, this instruction's Frozen blocks must be `exact`, and earlier instructions' planned deletions must be carried out; selected blocks already `exact` stay untouched, and each other one must be `unapplied` and land exactly once at a line boundary. A diverged block, nothing left to apply, or any failed check refuses the whole call with the mismatch and writes nothing, so diverged or already-applied text is never overwritten. It writes only those blocks' Location files: replaced lines take CRLF when the file has any, every other byte stays, and a new file holds its declared LF text. Specified work stays the agent's. A write failure stops as `safety-contradiction`. When an instruction still has `unapplied`, undiverged declared text, the command Construct returns for it is `apply`, with two exceptions: a `Red:` instruction whose Exact text is all unapplied and whose planned deletions are not yet carried out resumes at `prove` red once its Frozen text exists, and a Proof run that cannot launch keeps its `prove` route. On a `Red:` instruction, `apply` covers only Frozen text until red is observed, Exact text has started, or a planned deletion is carried out. Diverged text keeps the `prove` route for repair.
- **Red.** Only a Proof run that declares `Red:` is a new regression. `apply` its Frozen blocks and write any prose-specified test, implementing none of the change, then `prove` red while its Exact blocks are `unapplied`: it must fail, and the agent confirms the output shows the declared defect: the regression itself ran and failed because of the wrong behavior `Red:` names, however that failure surfaces (exit code, diagnostic, exception, or first failing assertion). A failure from a missing import, broken collection, unavailable tool, or another cause, or a regression left unexecuted because another case failed first, is not that red: repair a test you wrote and rerun red, otherwise stop as `plan-contradiction`. A red that passes while unapplied stops as `plan-contradiction` only when every kept Location has declared text; otherwise, if you already implemented the change, report an unrecoverable red gap, else make your tests implement every stated case and rerun red, stopping as `plan-contradiction` only when they still pass. One that cannot launch, or whose runner reports it blocked by its environment (such as lock contention or an exhausted deadline) with no failed case, is incomplete: stop without rerunning and report that environmental block, never as the red. Red after Exact text has started or a planned deletion is carried out is refused: report the red observation as an unrecoverable gap. Existing green checks need no red. Red carries the caller's next green `attempt` unchanged and consumes none. Red is Construct's observation; authored Runs still pass only on exit 0.
- **Green.** `prove` green checks the instruction's blocks and runs its Proof run. `unapplied` Frozen proof is the next action and uses no attempt; `diverged` Frozen proof stops as `plan-contradiction` (never edit frozen proof), so a mistyped Frozen block is local at red but terminal at green. A Proof run that cannot launch uses no attempt and is reported as unavailable, never as an implementation failure. A failing attempt returns the mismatch diff, full output, the instruction's diff, and the next attempt's command; a prose-specified test that misses a stated case is repaired within those attempts. Attempt 3 failing stops with that evidence. The caller retains each instruction's next unused attempt across invocations; commands validate 1-3 but cannot detect falsely supplied history. Missing or exhausted history stops this run, never resets to 1; a justified fresh run requires current authority and a trustworthy worktree. Successful green returns forward guidance derived from the sealed instruction order, never a resume scan or guessed counter. Before advancing, confirm the current instruction realizes its authored behavior and preservation rules, and judge its `Expect:`. For a non-final instruction, follow `proof.required_action` with that instruction's caller-held next unused attempt; `next_command` is null. The final green returns the authored `verify` after command. A `deleted` Location is mechanical proof by absence: green fails, using its attempt, while the path still exists. An instruction without mechanical proof retains `unprovable` and the same conditional forward guidance; it does not gain a fabricated proof result. `prove` first rechecks every earlier instruction's blocks and planned deletions; unproven earlier text points back to `status`, and becomes `plan-contradiction` only when a later edit changed text already proven in this run.
- **Final.** `verify` phase `after` reproves every block and planned deletion first: `unapplied` blocks and still-present `deleted` paths report `verification.instruction_unapplied` with a `status` command, including dependent anchors created by skipped earlier instructions. Diagnostic-only replay names those prerequisites but never counts projected text as applied. Real `diverged` blocks remain `plan-contradiction`, retaining mixed omission evidence. Exact proof covers declared text only, not semantic completeness.

## Reconciliation and completion

Before declaring completion, run one bounded reconciliation pass comparing the sealed Implementation against the actual final Git diff. The pass has one checkable outcome: the final diff realizes every instruction, contains no unauthorized material change, and preserves every authored and unrelated-work constraint. Derive the material changed paths from Git (`git status --porcelain` and the diff) and compare them against the authored `**Location:**` targets; an unattributed material path is removed or stops execution. Repair only mechanical execution mistakes already unambiguously settled by Blueprint; return every new semantic necessity to Blueprint with the exact evidence. A supported finding is never absorbed: stop with the evidence instead.

Completion is a caller-facing report: authored implementation applied in order, authored after-implementation verification passed, and the final diff realizes every instruction without unauthorized material change, with protected unrelated work and HEAD unchanged. Semantic completion remains grounded in the Blueprint's authored observable conditions; Construct does not invent acceptance criteria. A Completion Condition starting `Owner gate:` belongs to the owner it names: report it as pending, and never attempt or claim it. Inspect unexpectedly large changed-line counts for line-ending churn and renormalize only touched files. Commit, push, and other publication effects happen after completion and remain outside Construct.
