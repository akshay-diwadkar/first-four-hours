# Diagnosis Contract

`diagnosis.md` is the sole final investigation authority for accepted defects, risks, and worthwhile current improvement opportunities. The JSON bundle is temporary authoring/sealing input, not an investigation record or second diagnosis product. Start from [`templates/diagnosis-bundle.json`](../templates/diagnosis-bundle.json). `diagnosis_bundle.py`, reached through the single documented stateless CLI command, is the sole mechanical validation owner and the template is one valid example.

## Sealing input

Keep the template's `schema_version`. `diagnosis_context` contains `target`, `snapshot`, `evidence_root`, optional extra `material_surfaces`, material `limitations`, evidenced `ruled_out` eliminations, and next `open_probes`; each array may be empty. A Git snapshot declares canonical absolute `project_root`, canonical absolute Git-common-directory `repository_id`, and exact `revision`; a filesystem snapshot declares only its canonical absolute root. Identity is authored from the inspected project and must match at seal time; tooling never fills or rewrites it silently. A zero-finding bundle includes at least one material limitation that bounds what the current investigation established; it never asserts universal cleanliness.

`evidence_root` is `null` unless evidence cites captures; then it is the absolute directory holding them, outside the installed skill and target repository. Captures are files that an agent probe, the user, or an export produced where the target checkout cannot reach: run timings, job or environment exports, profiles, pasted notebook output.

Each material surface is a canonical repository-relative file `path` and inclusive positive `start_line`/`end_line`; omit `sha256` and the sealer records the span digest. Use this array only for an extra inspected span that materially qualifies scope/coverage and is not already finding evidence; it is not an inventory.

`findings` contains only accepted findings with stable `id`, readable `title`, present-state `summary`, material `impact`, neutral `cause_or_boundary`, `cause_status`, and inline `evidence`. `cause_status` is `demonstrated` when executed evidence shows that changing the suspected cause moves the effect as predicted, otherwise `inferred`; a reproduction of the symptom alone is `inferred`. Do not add severity, materiality, winner, candidate, rank, or category fields: current evidence and impact carry the consequence and confidence the next stage needs, while selection remains agent-owned. Every `observation` states what its record establishes and how that connects to the symptom, its location, or its magnitude; a citation alone explains nothing. Current `source|config|test` evidence declares `path`, inclusive line range, and observation; Git `history` evidence also declares an immutable revision. Omit their `sha256`: the sealer records each span digest. `command` evidence declares JSON `argv`, canonical relative `cwd`, `ran|not-run` status, and observation: ran records include exit code plus bounded stdout/stderr records; not-run records include a reason and no result. `external` evidence declares a locator and observation. `capture` evidence declares `path` relative to `evidence_root`, `sha256` of the whole file or, with optional `start_line`/`end_line`, of that normalized span, `provenance` (`agent-probe|user-supplied|exported`), single-line `origin`, and observation. Every finding needs at least one verified current-file/history/ran-command/capture record; external or not-run evidence is supplementary. A `demonstrated` cause needs at least one ran-command or capture record. Rendered output preserves authored finding, evidence, elimination, probe, and limitation order.

`ruled_out` entries declare a `hypothesis` and inline `evidence` under the same rules as a finding; record only eliminations a competent next investigator would otherwise pursue. `open_probes` entries declare `question`, `probe`, and `expected_outcomes` for each next discriminating observation when the pass stops short.

Investigation reasoning stays temporary: candidates, unevidenced rejections, reviewer outcomes, scores, rankings, measurements that did not become evidence, and notes are never persisted as diagnosis state; only evidenced `ruled_out` eliminations and declared `open_probes` persist. Unknown fields and any non-current schema version fail; regenerate from the template rather than translate or wrap them.

## Binding and authority

Paths use forward-slash relative form, stay inside the canonical root, traverse no symlink, and resolve to the declared regular UTF-8 file/blob and in-range span. An authored span `sha256` must match the sealer's line-ending-normalized span; omit it rather than hash by hand. Missing, moved, unsafe, undecodable, out-of-range, or mismatched evidence blocks sealing with the exact record named. Capture paths follow the same rules inside `evidence_root`; a capture without a line range hashes its raw file bytes. The sealer proves cited capture bytes are unchanged at seal time, never how they were produced.

Declared current-file evidence plus `material_surfaces` is the entire relevant-dirt boundary. Staged, unstaged, untracked, ignored, generated, vendor, and submodule content participates only when named there; unrelated dirt is never scanned or invalidating. Atlas/map state may orient investigation but supplies no identity, scope, evidence, freshness, or sealing authority.

Command stdout/stderr stores lowercase SHA-256, an excerpt of at most 4096 UTF-8 bytes, and `truncated`. Exact untruncated excerpts must match their digest; truncated digests are explicitly agent-declared because the sealer lacks full output. The sealer checks structure and referenced artifacts only: it never reruns commands or decides semantic sufficiency, finding acceptance, scope, ranking, or completeness. The agent owns investigation, interpretation, and finding acceptance.

## Publication and recovery

One documented stateless CLI command performs the sole validate/seal operation; there is no separate validation or checkpoint/resume command. On refusal, repair the named record and rerun; if identity or evidence changed, start a fresh diagnosis pass. Findings render first, each stating its cause status; non-empty `ruled_out` and `open_probes` follow as `## Ruled Out` and `## Open Probes`, then `## Diagnosis Context`, its limitations ahead of the snapshot, and the final receipt line. The command writes only `.first-four-hours/diagnoses/<slug>/diagnosis.md` under the target root; a same-slug reseal replaces it. Pass the top-level checkout as `--repo-root`; sealing refuses a tracked `.first-four-hours/diagnoses/` or a linked or non-regular `.first-four-hours/` or workspace entry. A non-Git target reports `git_ignored: false`. `.first-four-hours/diagnoses/` is never evidence, a material surface, or command cwd.
