# Codex

Checked 2026-11-16 against codex-cli 0.169.0 source, https://learn.chatgpt.com/docs/agent-configuration/subagents.md, and https://learn.chatgpt.com/docs/extend/mcp?surface=cli.

- **Directory:** `.codex/agents/` for a project install; `~/.codex/agents/` for a user install.
- **File:** `<name>.toml` with `name`, `description`, and `developer_instructions` (the instructions), plus `model` and `model_reasoning_effort` when chosen. The `name` field, not the filename, identifies the agent.
- **Name:** use `ffh_<role>`; the documentation's examples use underscores and do not establish that hyphens work.
- **Capabilities:** keep the shell for every agent, because Codex agents read and search files through it; turning it off with `features.shell_tool = false` can leave an agent unable to read. An agent file cannot block file edits or spawning, because sandbox and approval settings come from the parent session. So every agent's no-spawn limit, and every read-only agent's no-edit limit, are instruction-only here and need the user's choice. Skills come from the parent session, so `ffh-constructor` needs no extra setting. Per-agent web search is not documented: `ffh-researcher` uses whatever web access the session has, and the report says so.
- **Planner and batch-ops agents:** an agent file cannot limit MCP tools or which agents it starts, so `ffh_planner`'s limit to three agents is instruction-only and needs the user's choice, and the batch-ops choice says its restriction is instruction-only here. batch-ops counts as connected for that choice once `codex mcp get batch_ops` shows Provision's entry; its agents stay unverified until `/mcp` lists it. No prompt-cache lifetime setting is documented, so `ffh_planner` keeps the default.
- **Nesting:** `agents.max_depth`, default 1, stops a subagent from starting one, and Codex's `multi_agent_v2` feature ignores it. Read it in the project's `.codex/config.toml`, which wins, then `~/.codex/config.toml`. When it is under 2, offer to set it to 2 in the user file, the subagent-depth setting Provision writes, changing nothing else there, and write `ffh_planner` only after a yes. Offer to remove it when `ffh_planner` is dropped or on uninstall, saying Provision may have set it.
- **Models:** `codex debug models` prints the model catalog as JSON. Offer only entries without `"visibility": "hide"`, with the effort levels in each entry's `supported_reasoning_levels`. It is a debugging command: when it fails or its shape differs, ask the user.
- **Loaded:** reload behavior is not documented. Ask the user to start a new session and confirm that Codex can name and spawn the agent on the chosen model, and that `ffh_planner` can start `ffh_challenger`; until they confirm, it stays written but unverified.
- **batch-ops:** checked 2026-11-16 against codex-cli 0.166.0 and https://learn.chatgpt.com/docs/extend/mcp?surface=cli. Name it `batch_ops`, since hyphens are not established. Register it for the user on either install, since `codex mcp add` has no project scope and a project's `.codex/config.toml` would carry this machine's paths, and tell the user it applies to every project. Add with `codex mcp add batch_ops -- <python> <server>`; `codex mcp get batch_ops` shows it and `codex mcp remove batch_ops` removes it. Codex ends a tool call after `tool_timeout_sec` (default 60 seconds), so report that longer `batch_run` calls need it raised. Connected: the user confirms in a new session that `/mcp` lists it; until then it stays written but unverified.
