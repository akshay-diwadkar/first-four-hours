# Local persist

Read this reference only when persist runs with `backend=local`.

With `backend=local`, persist meaning also names `local_store`: a relative path to one explicit repository-local store directory, never inferred, never inside `.git`, and never inside the `.first-four-hours/` artifact root, whose skill folders Git ignores. An epic also names `epic_id`. Work-item ids and `epic_id` are lowercase slugs (`a-z`, `0-9`, `-`) that become store identities, so keep them unique across the store; `ticket-scope` and the Windows device names (`con`, `prn`, `aux`, `nul`, `com1`-`com9`, `lpt0`-`lpt9`) are reserved. `label` and `github_repo_url` apply only to GitHub and block a local run. The store is committable backlog truth, separate from the `ticket-scope.md` handoff.

Each record is `<local_store>/<id>.md`. Its first line is the managed `<!-- ticket-item: {...} -->` metadata: `id`, `kind` (`issue` or `epic`), `state` (`open` or `closed`), `parent` membership, `depends_on`, source `package`, and `payload_sha256`. The rest is human-editable Markdown. Only that metadata is authority; filenames, file order, and prose are not.

`reconcile` reads only the store's top-level managed records, needs no `reconciliation-input.json`, and plans each record as `create` or `existing`. A record from this same package is `existing` and is never rewritten, so later state, relation, and body edits survive. Any other record or file holding a planned id, or a record from another package whose `parent` or `depends_on` already names a planned new id, blocks before any write. Persisted records are durable truth: edit them directly, or persist new work as a new package with new ids; never re-persist an edited package over them. `publish` rechecks that plan, creates each missing record without overwriting anything (root first, dependencies before dependents), and reads each back. A publish stopped by `persist.local_write_failed` or `persist.local_output_unwritable` writes no result: repair the named cause and run `next` again to resume. Any other publish failure follows its diagnostic's required action. The result names the `anchor` id (epic root or single ticket) and every record; it never selects work.
